Luminary AI Engine API documentation

The repository includes an optional Express API server for self-hosted integrations. It is separate from the static hosted prompt-engineering interface; do not assume these API routes are publicly exposed unless the API service is separately deployed.

Core endpoints

  • GET /v1/health — service health.
  • GET /v1/info — API and capability information.
  • GET /v1/models — OpenAI-compatible model listing.
  • POST /v1/chat/completions — OpenAI-compatible chat completions.
  • POST /v1/ultraplinian/completions — multi-model response evaluation.
  • POST /v1/consortium/completions — multi-model synthesis route.

Authentication

The API middleware supports bearer-key authentication through GODMODE_API_KEY or GODMODE_API_KEYS. Production deployments must configure authentication and rate limits.

Research data is opt-in

API callers must explicitly set contribute_to_dataset: true to send request messages and final response content to the research dataset buffer. The default is false. Review the privacy page before enabling it; current dataset storage has no automatic PII scrubber.
